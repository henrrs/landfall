# Adaptive planner

The planner receives a `SemanticReadScope`, source profile, normalized source capabilities, runtime capacity, contract constraints and platform policy. It computes `max_in_flight` from CPU slots, memory-safe readers, platform safety cap and `maxSourceConnections`. It then estimates Arrow bytes from rows × row width and chooses `SINGLE` for small sources or when no safe bounded candidate exists.

SQL Server profiles index keys, PK/unique keys, existing statistics and up to 200 histogram steps per statistic. Candidate scoring rewards indexed, unique, high-confidence columns and penalizes NULL, skew and unindexed predicates. It considers numeric, decimal, temporal and indexed low-cardinality columns. Numeric and temporal ranges use open-ended outer partitions. Histogram boundaries can replace equal-width ranges when skew crosses the policy threshold. Nullable candidates get an explicit NULL bucket. Indexed value buckets have an `OTHER` complement; a hot value can be split by a second indexed numeric or temporal column. A skewed low-cardinality numeric leading component of a composite key can likewise split by its second component (`COMPOSITE`). GUID without a safe index-friendly predicate falls back to `SINGLE`. SQL Server does not enable expression-based hash partitioning because repeated non-sargable scans would be expensive.

Partition count combines estimated bytes, target and maximum bytes per partition, reader budget, desired waves and minimum useful size. A recent compatible manifest supplies partition durations, retries, splits and throughput. Slow or failed work increases logical partitions; very short work reduces them. Stable source/profile, contract, policy and capacity fingerprints allow reuse of prior physical boundaries within a history TTL; the new run receives a new scope and plan fingerprint. Poor recent performance prevents reuse. The plan includes reasons and version 2. A failed bounded numeric partition can split recursively to `maxSplitDepth`. See [partition sizing](partition-sizing.md), [skew](skew-handling.md), and [V1 completion](v1-completion.md).
