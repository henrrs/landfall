# Failure recovery and consistency

A partition is published only after a complete Arrow IPC file is validated. `.partial` files are never listed by a committed manifest. Failed runs leave their prior checkpoint untouched. Restart searches run metadata for the same contract fingerprint and previous checkpoint, reuses its HIGH, scope and plan, skips successful partitions, and commits only after all required partition files exist.

The renewable dataset lease prevents two active writers from committing the same dataset concurrently, while state compare-and-swap protects the checkpoint. The manifest records `BEST_EFFORT` for full reads and `BOUNDED_POSITION` for incremental reads. The latter freezes HIGH at run start, but is not a cross-connection snapshot: parallel queries may see different committed versions. Incremental correctness assumes position values do not move backward and eligible rows are not backdated inside an already captured HIGH. Full reads are not transactionally frozen. SQL Server snapshot settings are detected, never changed automatically; no `SNAPSHOT` guarantee is claimed without a shared read view.

The SQL profiler uses source row estimates and may under/over partition; open-ended edge ranges preserve value coverage. Published orphan files are downloaded in chunks to a temporary file and validated with Arrow IPC before a partition record is reconstructed. A corrupt orphan fails the run without advancing state. No backfill command is exposed in V1.
