# Skew handling

The SQL Server profiler reads existing histograms and derives a simple `max bucket rows / average bucket rows` skew score, equal-width occupancy, distinct estimate, NULL fraction and hot boundary values. The planner classifies that score as LOW, MODERATE, HIGH or EXTREME with Platform Config thresholds and records the classification in plan reasons. It lowers confidence for low sample coverage, many modifications or statistics older than 30 days. The planner penalizes skew, prefers histogram quantile boundaries when threshold is crossed, and can split an indexed hot value using a second indexed column. `hotValueFractionThreshold` catches a dominant equality value even when a coarse histogram reports modest bucket skew; `minimumHotValueRows` prevents elaborate splitting of tiny groups. Histogram steps are approximate, so partitions may still be uneven. Statistics with no blob are omitted safely; no full scan is triggered to create them. The executor retries failed partitions and splits bounded numeric ranges; unbounded edges cannot split safely with the current algorithm.

All value buckets include an `OTHER` complement, and nullable candidates include a NULL bucket. Property tests cover numeric, temporal, quantile, decimal and hierarchical boundaries. Extremely hot values without a safe secondary candidate remain one partition; hash expressions are not forced on SQL Server.

The SQL lab's 200-row sparse numeric and temporal fixtures produced a maximum of 34 rows in a quantile partition versus 199 rows with equal-width ranges, while both matched the reference SINGLE reader. This proves the boundary choice on those fixtures; it is not a throughput benchmark.

The 200-row `HotShape` fixture has 180 rows in `region=A`; its indexed composite key lets the planner split that value by `id`. The largest hierarchical partition held 29 rows, and the union matched SINGLE. This proves the strategy for that shape, while larger source-cost measurements remain open.

`CompositeHot` uses a numeric two-column primary key with a hot leading component. The `COMPOSITE` strategy applies the same disjoint value-range pattern to the second key. Other composite distributions may fall back to SINGLE until safe boundaries are available.
